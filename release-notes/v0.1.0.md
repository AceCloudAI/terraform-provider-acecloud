## v0.1.0 — First official release

This is the first release of the AceCloud Terraform Provider under the official `AceCloudAI/acecloud` Registry namespace.

### What's included

**Resources** — 21:

- Compute: `acecloud_instance`, `acecloud_key_pair`, `acecloud_snapshot`
- Storage: `acecloud_volume`, `acecloud_volume_attachment`, `acecloud_volume_backup`
- Networking: `acecloud_vpc`, `acecloud_subnet`, `acecloud_router`, `acecloud_router_interface`, `acecloud_security_group`, `acecloud_floating_ip`, `acecloud_floating_ip_association`
- Load Balancing: `acecloud_load_balancer`, `acecloud_lb_listener`, `acecloud_lb_pool`, `acecloud_lb_pool_member`, `acecloud_lb_health_monitor`
- Auto Scaling: `acecloud_auto_scaling_template`, `acecloud_auto_scaling_deployment`
- IAM: `acecloud_api_key`

**Data sources** — 5:

- `acecloud_flavors`, `acecloud_images`
- `acecloud_vpcs`, `acecloud_routers`, `acecloud_security_groups`

### New attributes in this release

- `acecloud_instance.private_ip` (computed) — primary private IP address. Useful as a load-balancer pool member address.
- `acecloud_instance.public_ip` (computed) — public IP address when a floating IP is associated.
- `acecloud_key_pair.private_key` (computed, sensitive) — generated OpenSSH private key, returned on create when `public_key` is not supplied.
- `acecloud_volume_backup.force` (optional) — set to `true` to back up a volume that is still attached and in use. Defaults to `false`; leave unset when backing up an unattached volume.

### Documentation

Every configurable argument with a fixed set of accepted values now lists the values directly in its description. This includes load-balancer protocols and algorithms, health-monitor methods, security-group directions and ethertypes, billing types, and all computed `status` / `provisioning_status` / `operating_status` fields. The `volume_type` and `region` arguments — which vary by region and account — point to the AceCloud console for the per-account list.

### Provider configuration

API-key authentication, with `region` and `project_id` required at plan time so `terraform plan` is deterministic across machines:

```hcl
provider "acecloud" {
  api_key_id           = var.acecloud_api_key_id
  api_key_secret       = var.acecloud_api_key_secret
  api_key_service_name = "terraform"
  region               = "ap-south-noi-1"
  project_id           = var.acecloud_project_id
}
```

`api_url` is optional and defaults to the production AceCloud endpoint.

### End-to-end guides

The Registry page includes six guides covering common patterns:

- Single instance with SSH access (validated live)
- Web tier behind a load balancer
- Auto-scaling pool with integrated LB
- Volume snapshot and restore (validated live)
- Volume backup and restore (validated live)
- Multi-region and multi-project setups (validated live)

### Notes

- The `acecloud_api_key` resource is import-only: keys must be created from the AceCloud console, then brought under Terraform management with `terraform import`.
